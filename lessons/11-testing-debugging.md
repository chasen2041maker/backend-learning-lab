# 第 11 课：测试证明边界，调试寻找证据

## 测试层次

| 类型 | 主要证明 | 不证明 |
| --- | --- | --- |
| 单元测试 | 业务规则、状态机、错误分支 | 真实数据库兼容性 |
| Repository 集成测试 | SQL、事务、索引和驱动行为 | 完整用户流程 |
| 契约测试 | 路径、字段、状态码、事件兼容 | 业务质量 |
| E2E | 多组件关键流程 | 所有边界条件 |
| 负载/故障测试 | 容量与恢复 | 业务逻辑全部正确 |

Fake provider 通过只能说明协议和本地逻辑可重复，不能写成“真实供应商已经生产验收”。

## 测试结构

```text
Arrange：准备输入和依赖
Act：执行一个行为
Assert：验证外部可观察结果
```

优先断言行为和状态，不要把测试绑死在内部函数调用次数上。

## 调试顺序

1. 稳定复现；
2. 保存预期、实际、完整错误；
3. 用 request/trace/event ID 串联日志；
4. 找到第一个错误状态，而不是最后一个报错；
5. 提出可证伪的假设；
6. 做最小实验；
7. 修复根因；
8. 运行原复现和回归测试；
9. 记录证据。

## 审查 AI 生成代码

- 是否遗漏 tenant/owner 条件；
- 是否吞异常或无限重试；
- 是否在事务中调用外部服务；
- 是否存在并发覆盖和重复副作用；
- 是否把测试环境能力写成生产能力；
- 是否写死密钥和地址；
- 测试是否真的执行失败场景。

## 练习

先把一个状态转换规则故意改错，确认测试失败；再修复并在 Debug Log 写下“失败证据”和“为什么不是其他原因”。
