# 第 4 课：先有契约，再有实现

## 契约解决什么

客户端、BFF、服务和测试必须对字段、状态码和错误语义达成一致。只在聊天中约定，很容易出现“前端以为可空、后端以为必填”。

本仓库使用：

- `contracts/api-contract.md` 描述外部 HTTP；
- `contracts/event-contract.md` 描述异步事件；
- 练习中再把关键接口写成 OpenAPI。

## 兼容变化

通常兼容：

- 增加可选响应字段；
- 增加新端点；
- 扩展客户端能够忽略的事件字段。

通常不兼容：

- 删除或重命名字段；
- 改变字段类型；
- 复用旧字段表达新含义；
- Protobuf 复用已删除字段编号。

## 分页

小数据可以 Offset 分页；不断增长或高并发列表更适合 Cursor：

```text
GET /api/v1/tickets?limit=20&after=01J...
```

游标必须建立在稳定排序键上，常见是 `(created_at, id)`。

## 身份传播

客户端提交的 `user_id` 不可信。可信身份应由网关验证 Token 后注入，owner service 再检查资源归属。
